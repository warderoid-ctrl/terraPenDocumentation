Answered, and what changed

All eight questions are written into the guide on branch docs/first-time-user-rewrite.

Q1
Homing is now the first step of every sessionThe machine ships with limit switches, so homing leads, and setting your own zero is documented as the follow-on rather than the primary method. The old jog-to-the-corner routine is gone.
Q2
Working area is A2 — 594 × 420 mmCorrected throughout. The YAML page now states explicitly that max_travel_mm does not define the usable area, since soft limits are off — otherwise the next reader hits the same 300 mm confusion.
Q3
terraForge leads the guideNow the recommended route, pointing at the latest RC rather than a pinned tag, with a note that RC is the build to take while development is active.
Q4
The USB warning is goneReplaced with the real procedure: select USB in terraForge's machine settings; jogging, homing, pen control and file upload all work over the cable.
Q5
New page: Fitting the toolheadThe stepper ships unattached — four screws and the supplied hex key. The guide previously had no assembly step at all, which would have stopped a new owner on day one.
Q6
Pen height rewritten around the real methodNib to paper, set Z zero, jog +5 mm — and the reason 5 mm exists (paper warping mid-plot). The puck is removed from the box list, and the guide now says to set zero fractionally into the paper so the spring tracks an uneven bed.
Q7
Wi-Fi setup gained a way to tell it workedYour check is now the centrepiece of the page: if terraPen has vanished from the available networks, it joined yours; if it is still there, it fell back. Far better than telling people to dig through router settings.
R1
The web UI Home button does homeIt homes X and Y — there is no switch on Z. The hedge sending readers to terraForge for "real" homing is gone, and the first-plot page now says explicitly that Z is not homed, which is precisely why you set it by hand against the paper in the next step.
R2
terraForge 1.4.0-rc7 confirmedAlready what the home page said; no change needed.
R3
USB page is terraForge only nowThe Lightburn walkthrough is gone, and with it the unanswerable question of whether its movement bug was ever fixed — the page no longer makes a claim either way. Lightburn survives as a documented alternative, not a recommendation.
R5
Permanent Discord invite keptThroughout the guide.
Q8
Versions recorded on the home pageFluidNC 4.02 and terraForge 1.4.0-rc7, so future readers can tell how current a page is.

Still open

One cosmetic, and two that surfaced from reading the terraForge screenshots closely.

R4

Which web UI version?

Low priority

The home page records FluidNC 4.02 and terraForge 1.4.0-rc7, and leaves the web interface out. Worth filling in whenever you find it — it is the marker that tells a future reader how stale a page has become.

R6

terraForge's default machine profile is not an A2 terraPen

Would spoil a plot

The shipped TerraPen (Default) profile is set to a 220 × 200 mm bed. On a 594 × 420 machine, artwork positioned against that profile lands in the wrong place, and nothing warns the user.

Bed width (mm) 220 Bed height (mm) 200 should be 594 420

I have put a warning on the terraForge page telling people to set it themselves. But this looks like it should be fixed in terraForge instead — worth raising with Mark.

R7

Is the host terrapen.local or fluidnc.local?

Confirm

This guide says terrapen.local throughout, which you confirmed. terraForge's default profile ships with fluidnc.local in the Host field.

I need: which actually resolves. I have written terrapen.local with "or the address your router assigned" as a fallback, so the page is safe either way — but the two defaults disagreeing will confuse people.

The terraForge repository already had them under an MIT licence, so the canvas, machine configuration, G-code generation, jog panel and running-job shots are ported and live, credited on the terraForge page. They also corrected labels this guide had been guessing at — the buttons are Run Homing and Set Zero, and the connection choice is Wifi / Usb. Worth re-checking them against 1.4.0-rc7, since they were shot for user guide 1.3.
Two conventions worth adopting while you shoot. Rename files without spaces or symbols — AlarmOff$X.png contains a $, and most existing names contain spaces, which makes them awkward in URLs and some tooling. And shoot UI captures at a consistent width so the pages stop jumping between image sizes.

How to shoot them so they work in the docs. Silent, and short enough to loop — documentation video is watched with the sound off, so anything essential has to be visible, not narrated. MP4 (H.264) rather than GIF: far smaller at the same quality, and it can be paused. Crop screen recordings to the panel in question rather than capturing the whole desktop, or the detail is unreadable on a phone. Give each one a poster frame so the page does not show a black rectangle before playback.
Where to put the files — decide this before you shoot. Video committed to git stays in the repository's history forever, and this repo has no Git LFS rules set up despite an [lfs] section lingering in an old config. Two workable options: keep clips under a couple of megabytes and add LFS tracking for *.mp4, or host them on YouTube or Vimeo and embed. For a docs site this size I would host the long ones externally and commit only the short loops. Say which you prefer and I will wire up the markup and, if needed, the LFS configuration.
One editorial rule. Video supplements the written steps, never replaces them. Nobody can skim, search, or copy a filename out of a video, and a reader halfway through a plot with inky hands needs the text. Every video should sit alongside the steps it illustrates, not in place of them.

Content gaps

Things the guide still does not cover. None block publishing, but each is a question owners will ask.

Safety

Nothing tells people to keep fingers and hair clear of a moving gantry, or what to do when the pen crashes. One short section covers it.

Maintenance

No guidance on belt tension, rail cleaning, pen storage, or what wears out. Owners will ask on Discord instead.

Bed flatness

You described setting the nib slightly into the paper because beds are not flat. That implies a fuller page on levelling and what "good enough" looks like.

Pens and paper

"Most pens fit" is all there is. Which pens and stocks work, and what to avoid — the most common beginner question for any plotter.

The empty blog

docs/blog/index.md contains the single word "Blog" and is not in the navigation. Start it or delete it.

A stray file is published

docs/all text.rtf is 7 bytes, effectively empty, and is copied to the live site as a download. It should go.
